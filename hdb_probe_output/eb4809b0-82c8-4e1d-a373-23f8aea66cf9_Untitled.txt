Use chronological evaluation. Randomly splitting adjacent observations would
make the results look better than they are. Match labels by timestamp, handle
missing intervals explicitly, and build features only from information available
when the prediction was made.
Every prediction acquires its label when the observation approximately 30 minutes
later arrives. No manual annotation is needed. This is the main reason the
retraining requirement fits this topic well.
The automated retraining cycle would be:
1. Process observations collected since the previous run.
2. Validate freshness, coverage, duplicates, and capacity values.
3. Construct features and matured labels.
4. Train a candidate using the rolling historical window.
5. Compare it with the baseline and deployed model on withheld recent data.
6. Save the model, metrics, training window, data references, and Git commit.
7. Promote it when it passes the evaluation criteria; otherwise keep the existing
deployed model and record why.
Retraining happens every three days; replacing the deployed model depends on
the evaluation.
